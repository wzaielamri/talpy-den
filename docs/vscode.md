# In VS Code

Talpy Den for VS Code is the same dashboard as a view in VS Code (or a wide editor tab): every Claude Code chat you have running, on this computer and on your SSH hosts, which need you, which work, each account's plan usage, and Talpy acting it all out. It brings its own copy of the backend, so it works on its own or next to Talpy Den on Plasma or GNOME, also in Remote-SSH windows. The extension's own page shows a short [README](../vscode/README.md); this is the whole story.

## What it shows

- **Every chat**, grouped by account: waiting for you (permission prompt, question…), working, your turn, finished. Background jobs too, and the subagents a chat runs.
- **What a subagent did**: click one in a chat's agent tree for the task it was given, its tool calls and tokens, its last steps and its report. **Open the whole run** shows every step in Talpy Den's tab for Markdown (the start of each result, messages from the chat, the report). Claude Code can't open a subagent from outside, so the run is rendered from its transcript; an SSH host's is fetched over ssh.
- **Changes the moment they happen**: the extension watches the files Claude Code keeps for its chats, so a chat that starts, ends, starts working, asks for something or finishes its turn shows at once (also when you answer or interrupt it in its terminal), with its pet and notification; in between it checks far less often. A line under the big Talpy says what the working chats do right now, taking turns between them (click it for that chat's tab). **Talpy Den: Live Mode…** shows each step of each chat as it happens too (a hook in Claude's settings that Claude doesn't wait for).
- **Focus** (the button at the top of the view): only what needs you, as full rows (their questions, Allow and Deny), the chats that finished a turn you haven't looked at yet (until you open that chat), one line for each chat at work with what it does now, and how the rest stands; **Show everything** goes back.
- **What a chat is doing, without switching to it**: a line under each chat says what it's on right now (*▸ Bash: npm test*), what it needs, Claude's recap of it (when you come back to a chat after a while, Claude Code writes one: *You asked …; Next step: …*), or the first line of Claude's last reply. Click it for your last prompt, Claude's whole reply, the chat's task list and its changed files. A chat with a task list has a small bar at the start of that line that fills up as tasks get done (*2/4*); a chat in plan mode, auto mode, accept edits or don't ask says so, and one that bypasses permissions says so in red.
- **Chats a usage limit stopped** say so in red, with when the limit resets; their pet's battery runs low, and the notification says the chat hit the usage limit, not that it finished. Once it has reset, a notification says which chats can go on. Meanwhile **Continue on …** under the chat moves it to another account with room left (shared with it, then reopened there), or **⏱ Go on at 10:41** has it go on by itself in the background once the limit resets, in the permission mode it had and on the model and reasoning effort it last ran on, which the answer names (*Opus 5.5 · xhigh*); a background chat that's still running takes that in where it is, as `claude agents` answers one (a terminal that shows it stays on it); otherwise an idle Claude that still has it open quits first (one still running commands it started in the background, a server say, is waited for, and ended 15 minutes after the go-on's time, with a notification as it starts waiting and as it ends them). **↻ Keep going** beside it does that after every later limit too, until the chat is done (with no reset to go by, out of usage credits say, it tries again after 2, 5, 15, 30 and 60 minutes, then gives up and says so); a chat at work gets the same from its ↻ button. A chat on an SSH host or in a container can keep going too: it's kept on this computer and goes on from here over ssh, as a go-on you queue there does, once the host's latest check says a limit stopped it (a host that hasn't answered for 15 minutes waits, and its *Keeps going* tag says so). A go-on (or task) queued for a host or a container that couldn't be reached when its time came (Disconnect, no network, a stopped container) starts by itself once it answers again; one the host turned down, or didn't answer in time (it may have started there), waits for you. And one of a host or a container that isn't shown (you unpicked it, or containers are off) is still listed, where the hosts go, with **Show** and **Stop** or **Cancel**: it goes on all the same (Talpy Den still checks that host or container, as often as the ones shown, while something of it keeps going or is queued). A chat that keeps going stays listed until it's done or you turn Keep going off, also once its terminal is closed; and when closing its terminal makes Claude move it to the background under a new id (a copy of its history), Keep going, its go-on, its row (with what's unfolded in it), its pet, its star, its name, a Hide and its open Talpy Chat tab follow it there (its row's *Background* tag says when it moved; the Projects tab and search list it once, under the new id), and the old id is never resumed (that made two copies of the conversation work at once). In **Recent chats**, click a chat's **Limit** tag (once) or **↻** (keep going) for the same. Stopping a chat that keeps going (■) asks whether to leave Keep going on (**Stop**: it goes on after the next limit) or to turn it off too (**Stop and turn Keep going off**).
- **Recent chats, a page at a time, and the Projects tab**: under its running chats, each account lists its **Recent chats**, **★ Starred chats** and **★ Starred plans**, each flat and newest first, as many at a time as `talpyDen.recentChats` (**Show N more** under a list shows the next ones, its title says how many of all show, *Recent chats (5 of 23)*, and folded again it starts over), then its `CLAUDE.md` as one line: your instructions for every chat on the account, to read or edit. The **Projects** tab has everything else by project (a chat's git repository, also from one of its worktrees, else its folder), newest first, each folded until you open it: when Claude last worked there, a dot for each of its open chats, a button for a new chat there and one to hide it. Opened, a project shows its open chats, Claude's last recap of it, and its chats, plans and memories as the same lines as under an account, with their buttons, a page at a time, each with the account it's on when the project is on several; a line's folder says only the part below the project's, and *(not there any more)* marks a project whose folder is gone. Time and money by project are in the Recap, whose **Where Claude worked** opens a project here.
- **Star chats and plans** (the star button next to them): each account lists its starred ones under **★ Starred chats** and **★ Starred plans**, however old they are. ★ unstars one.
- **Find a Chat…** (the search button in the view's title bar): every chat with all the words you type in its name, folder or prompts, here and on the SSH hosts shown. Pick one to go to it, or to reopen it. It finds project folders (pick one for a new chat there), plans and memories too. Each kind, and each computer, folds under its heading (the chats show at first); the button in its title bar unfolds them all.
- **Plans**: a chat that wrote a plan in plan mode gets a **Plan** tag (with the plan icon) that shows it rendered in a Talpy Den tab (as Talpy Chat renders replies; it loads no picture from the web, where VS Code's Markdown preview would, and follows the file as it changes), and a pencil tag that opens its file to change it (as does **Open as text** in that tab). There, the **+** next to a line adds a comment for Claude, and **Send Feedback to Claude** (the send button in the title bar) sends your comments and your changes to the chat that made the plan: Claude revises it in plan mode. Every plan is in its project on the **Projects** tab (and under **★ Starred plans** once you star it): open one, carry it out in a new chat (the plan is its first message, with what you add), go back to the chat that made it, share it with your other accounts (sharing a chat shares its plan too), hide it (the struck-out eye) or delete it (the trash button). Plans Claude keeps in a project's own folder (its `plansDirectory` setting, or `.claude/plans`) are listed too, each once, and take comments and **Send Feedback to Claude** as the others do. **Move to project…** puts a plan's file into a project's own plans folder, and in the **Projects** tab you can drag a plan by its name onto another project's card: either way it asks first (the project, *Keep this project's new plans there too*, whether git would show it, keep both or replace), and nothing moves until **Move**; Esc, Cancel or a click elsewhere leaves it. One in a project's folder has **Move back** to its account. A plan whose project isn't known says *chat gone* where its folder would be ([features](features.md) has the details).
- **Queued tasks**: a task started in the background can wait for a day and time you pick (**Later, at a time you pick…**), or, when the account is at its limit, until the limit resets (**After the limit resets**), then starts by itself. The account lists its queued tasks with when they start: start one now or cancel it (one with text you wrote asks first, since the text goes with it).
- **Chats changing the same files**: chats that are open and changed some of the same files get a red **⚠ Same files** tag naming the other chat (and a notification), since two chats editing one file can overwrite each other.
- **Memories**: each project on the **Projects** tab lists what Claude remembers about it and about you (**Memories**), and each account its own `CLAUDE.md`: read one in Talpy Den's tab for Markdown, edit it, hide it (the struck-out eye) or delete it (the trash button). Pointing at one shows its folder, *(not there any more)* when that folder was moved or deleted.
- **Hide or delete**: the hide button (a struck-out eye) on a finished chat, a plan, a memory or a project (on the **Projects** tab) hides it from the view; nothing is deleted, and a hidden chat comes back by itself if it runs again. The view's **⋯** menu and the Command Palette bring each kind back (**Talpy Den: Show Hidden Chats Again**, **… Plans …**, **… Memories …**, **Show Hidden Projects Again**), each while something of that kind is hidden; an SSH host's eye button offers its own. The trash button beside it deletes a finished chat (also under **Recent chats**), a plan or a memory: it asks first, on a line under it, saying what goes and on which accounts (*Delete “Fix the build” on work and personal? It goes to the Trash with its subagents and checkpoints; the Recap keeps its numbers.*), then moves it to the Trash: a chat with its subagents and checkpoints on every account it's shared with, a plan on every account it's on, a memory with its line in that folder's `MEMORY.md` (the rest stays as it was). An SSH host's goes to that host's Trash. A chat open in Claude isn't deleted (*It's open on work. Exit it there first.*), and neither are an account's `CLAUDE.md` or a project (hide it instead).
- **What a chat changed**: its **±3** tag opens VS Code's changes view with each file as it was before the chat and as it is now (or only the last turn: **Last turn** in the unfolded peek). The files come from the backups Claude Code makes before it edits a file; a file with no backup is compared with git's last commit. Changes made through shell commands aren't tracked.
- **Plan usage**: the 5-hour and weekly limits of each account with when they reset, today's and this week's tokens. Each bar also shows where your pace leads by the reset (the lighter part) and where an even pace would be by now (the tick); when the 5-hour limit would run out first, a line says when.
- **A usage cap** (`talpyDen.usageCap`, off until you set it): once an account's 5-hour or weekly window reaches that share, its chats at work on this computer are stopped, once in that window (in tmux and in a Claude Code panel the turn is interrupted and the chat stays open). Queued tasks wait until the window resets, and chats that keep going go on then. Chats you start or answer yourself afterwards aren't stopped again.
- **Your last days**: click an account's token line for its last 14 days: tokens per day as bars (hover one for its chats and prompts), the totals, the busiest folders and the models used. The prompts come from Claude Code's prompt history, the tokens from the transcripts.
- **Your days with Claude**: the view's **Recap** tab shows a day, your last 7 days, your last 30 days or everything since your first chat (**Day | Week | Month | Overall**; Claude Code deletes chats after 30 days, but the Recap keeps their numbers unless `talpyDen.recapHistory` is off; turning it off asks first when the history holds such chats or your plan's windows that ended). For the 7 days, from the big picture to the money: how long you were at it, how long Claude worked, your prompts, its tokens and what they'd cost at Claude's API prices, against the week before (while today isn't over, the days before count up to this time of day), with a trend line of the last five weeks under each number; what Claude did (tool calls, commands, edits with their files and lines, subagents, web searches, compactions, and the other tools it used most); a row per day on a timeline, with when you were at it, when Claude worked (darker where several chats worked at once) and when it waited for your answer (point at a day to see what went on then), with a red mark where a usage limit stopped a chat (click a day for its chats; a day the clocks change is drawn by its own clock, under the same hours as the others; a month's and everything's rows say their days: *23–29 Oct*); on today's **Day**, how full your plan's windows are now and how they filled up, and folded under it, your plan's limits over time; on a **Day**, one timeline chat by chat, the day's own row (*All chats*) on top and each chat's time and cost at its end, in place of the day's row and the chats it worked on most; the projects (click one of this computer's to open it on the **Projects** tab, an SSH host's for its chats) and the chats it worked on most (click one to bring it up); what the same work would cost at Claude's API prices, by model, with what the cache saved; and what would use less of your plan: the tips of Claude Code's own `/usage` (*Start fresh when you switch tasks*, *Save max effort for hard tasks*, …), each with the share of the usage it touches (*86% of usage*) and a command to copy, its icon saying where it comes from, and what coming back to chats after their cache had expired cost. For all your accounts or one, with the SSH hosts shown, in US dollars or your currency (`talpyDen.recapCurrency`). It's read from the chats' transcripts, so it uses no tokens, and only while the tab is open: the first time takes a few seconds, after that only what's new is read. On Mondays a notification sums up the last 7 days, with the SSH hosts shown, as the Recap counts them; **Open the Recap** shows them (`talpyDen.mondayRecap`).
- **The permissions you gave, in one place**: the view's **Permissions** tab lists everything that lets chats go without asking you, here and on the SSH hosts shown: the rules and modes in your settings, your administrator's and every folder's `.claude` settings, approved `.mcp.json` servers, the settings that loosen a check, and the folders you trusted. **Revoke** changes that one entry in its file (on the host for a host's; a trusted folder is marked untrusted). Under it, the permission prompts you answered in the last 7 days, with the rules that would have let the most of them through (**Allow** writes one, **Undo** takes it back; `talpyDen.recapRules` leaves them out).
- **A chat's recap**: the unfolded peek ends with the chat's numbers: your prompts, how long Claude worked (each turn from your prompt to its last step), its tool calls by tool, its tokens with its subagents', and what it would cost at API prices when the status line says so.
- **The chat that needs you, one key away**: **Ctrl+Alt+Shift+C** (**Talpy Den: Go to the Chat That Needs You**) opens the chat that has waited longest; press it again for the next one, then the chats that finished while you weren't looking. With none, it shows the view.
- **Answer the oldest prompt from anywhere**: **Ctrl+Alt+Shift+Y** (**Talpy Den: Allow the Oldest Prompt**) allows the permission prompt of the chat that has waited longest, once (a plan: approves it), and **Ctrl+Alt+Shift+N** (**Talpy Den: Deny the Oldest Prompt**) denies it (a plan: keeps planning); the status bar says what was answered. They take the permission hook (see *Permission prompts* below).
- **While you were away**: back at VS Code after 5 minutes or more, one notification (and a card at the top of the view) sums up what happened: chats that need you, finished or failed, limits that reset. Meanwhile, notifications of finished chats wait for it.
- **SSH hosts**: the chats on the hosts you pick, side by side with this computer's. A host that wants a password shows **Log in…**: a terminal where `ssh` asks for it, so the extension never sees it; the checks then use that connection (until 30 minutes after their last use, logging out, or the host's **Disconnect** button; terminals already open over it go on, and it closes with the last of them). A host's VS Code chat with no VS Code window connected to the host asks once per host before VS Code connects there (*Open VS Code connected to lab? Its VS Code server can read your clipboard and open links here.*, or **Open in a terminal instead**).
- **Containers**: **Talpy Den: Show Claude on SSH Hosts and Containers…** also lists your Docker, Podman and nerdctl containers, here and on each connected SSH host (the running ones and those active in the last `talpyDen.containerDays` days), with **Reload**. A picked one shows like a host: a stopped one says so with **Start**; its chats open in a terminal inside it (`docker exec -it`); a Dev Containers window shows its own container's chats by itself (the one of the engine Dev Containers runs, by its name, or its project folder and config file; when two would fit, none), and VS Code chats in a container reopen through Dev Containers (with no window attached to it, after a yes once per container: *Open VS Code attached to web? Dev Containers shares your SSH agent and Git credentials with it.*, or **Open in a terminal instead**). It needs `python3` in the container; nothing is installed there. `talpyDen.showContainers` off: no container engine is asked anything.
- **Notifications** (and a sound) when a chat needs you or finishes a long turn, or a usage limit stops it.
- **The status bar**: Talpy in the panel icon's pose for what the chats do (at work, popped up when a chat needs you, smiling on your turn, asleep), how many chats need you or work, the 5-hour usage, and with two or more accounts which one VS Code's Claude runs on, its usage next to it (**1 · work 42%**), all in one item: click it to open Talpy Den, or **Change the default account…** in its hover.
- **Talpy**: one pet for the whole dashboard, one per chat (in the same order as the list: the chats that need you first, the others in the order they started; its bar in the pet's color), each acting out its chat. Talpy lives in a burrow: it digs over to another spot instead of walking, a new chat's pet digs up out of the ground, and one whose chat leaves the list waves and digs away. Click a pet to go to its chat (its terminal or Claude Code panel), drag one out of its burrow (it hangs on to the rim for a second first), double-click the big one. Double-click the big one's stage a little away from it for a cookie, now and then of another flavour: it runs after it as you drag the cookie around (let go and it floats down; pick it up again any time), and eats it. When your system asks for less motion, the pets keep still: the big Talpy doesn't dig about, a pet whose spot moved is just there, a cookie is eaten where it lies, and the light and the stars don't pulse or twinkle.
- **Shared chats**: with two or more Claude accounts on this computer (or on an SSH host), a finished chat's share button continues it on another account (say, when one hits its limit), shares it with all of them, or keeps it on one again (see "Good to know" for adding a second account).
- **Accounts**: **Talpy Den: Claude Accounts…** (the view's **⋯** menu) lists the Claude accounts of this computer or of an SSH host in the view: whom each is logged in as, which one is the default, which ones VS Code's Claude and plain `claude` run on. **Add Account…** (also in the view's **⋯** menu) makes a `~/.claude-NAME` folder and opens a terminal with Claude's own login; an account can log in or out, get a `claude-NAME` command, become the default, or be removed (to the Trash). An account that isn't logged in shows **Log in…** in the view.
- **One default account**: listed first (here and in Talpy Den on Plasma and GNOME) and marked **default**, its usage in the status bar, and both VS Code's Claude and plain `claude` run on it (see "Good to know"). Each SSH host has its own: what Claude Code there runs on.

## Your side, also over Remote-SSH

The extension always runs on your computer (`"extensionKind": ["ui"]`), even when the VS Code window is connected to a server with Remote-SSH. So one view shows your local chats *and* the server's (and any other host's), whichever machine the window is on:

```text
 your computer                                 an SSH host
┌───────────────────────────────────────┐
│ VS Code window (local or Remote-SSH)  │
│   Talpy Den view (webview)        │
│   extension: runs here, always        │
│     ├─ reads ~/.claude* here          │       ┌────────────────────────┐
│     └─ ssh host 'python3 -' ──────────┼─────► │ reads its ~/.claude*   │
└───────────────────────────────────────┘       │ (nothing is installed) │
                                                └────────────────────────┘
```

The host your window is connected to is shown without setting anything up. Other hosts: **Talpy Den: Show Claude on SSH Hosts and Containers…** lists the ones in `~/.ssh/config`. A host needs key-based login, or **Log in…** where it wants a password (Talpy Den never sees it), and `python3` 3.7 or newer; nothing is installed there.

**Clicking a chat opens it in an editor tab:** the conversation as it goes, drawn the way Claude's terminal draws it: a dot before each reply and tool call, Claude's replies rendered (headings, lists, code blocks with a **Copy** button, tables; it says *Copied* once it has, and for a command Claude wrote for its prompt, `! chmod …`, it copies the command without the `!`), each tool call on one line with what came of it under it (*● Bash(pytest) ⎿ 3 passed*, the dot green or red; click it for what it ran and got). While Claude works, a line at the end says what it's doing and, at its end, how long it has worked on your message and how many steps it took (*4m · 12 steps*), with **Stop**: what Claude does now stops, as Esc in its terminal, and the chat stays and takes your next message (the conversation says *Interrupted*). Stop is there for a chat in one of this window's terminals or in tmux (Ctrl+C) and in the background (Talpy Den types the Esc through Claude's background service, at the size a terminal attached to it has, so that terminal doesn't change; Claude Code 2.1.318 and later 2.1 versions); elsewhere the line's tooltip says where to stop it. The header's *Context 69% left* says what's left of the chat's context before Claude compacts it on its own, counted as Claude Code counts it, in the warning colour once that's close (its tooltip: the tokens used of its model's window, and `/compact` to choose what it keeps); none when it can't be known (a model Talpy Den doesn't know). A line comes before the first item of each new day (*Today*, *Yesterday*, *Mon 3 Nov*), none before the first; with the pointer on a message, yours or Claude's reply, its time (*14:32*, *Yesterday 14:32*) and **Copy** show over its top right corner (a reply as Markdown, as Claude wrote it, all of it: one the tab shows cut is read whole first; yours as you wrote it; it says *Copied* once it's on the clipboard). **?** in an empty box lists Talpy Chat's keys, and buttons' tooltips name theirs (see *Commands* below). Scrolled up while new messages come in, *2 new ↓* shows over the bottom of the conversation: a click goes to the end. **A−** / **A+** (or Ctrl+wheel) set the text size (`talpyDen.chatTextScale`). Below it, a box to reply (Enter sends, Shift+Enter starts a new line, **Ctrl+V** pastes a picture, shown under the box): **Send**, or **Send when this turn ends** (kept, and sent once the turn is over). Your message shows at once, dimmed (*Sending…*) until the chat has it. One sent while Claude works waits 5 s first, *Queued · goes to Claude in 5 s*, with **Edit** (back in the box; ↑ in an empty box too), **Send now** and **Cancel**; then Claude takes it in at its next step. ↑ in an empty box also brings back the messages you sent before, one at a time, as in Claude's terminal. **Suggested replies:** once Claude's turn is over, small chips above the box offer a reply in one click (nothing is sent without one): first the answers to the question Claude ended with, found by its shape (its options as Claude numbered them, the one it recommends in bold; the two halves of an either/or; *Yes* and *No* in the question's language), then what you usually reply after a turn that ended the same way (after a usage limit, a chat that stopped…), from your own chats on that account, shown only when it's a good share of what you sent then. A click sends it as if you typed it; Shift+click, or *Edit before sending* on its right-click menu, puts it in the box to add to it; Alt+1…4 picks one; *Don't suggest this* hides one of your usual replies for good. They never show while Claude works or asks, nor once you type, and after five messages in a row that weren't one of them, none for half an hour. What you type is completed in grey from your usual replies (Tab or → takes it). `talpyDen.suggestReplies` turns them off (**Talpy Den: Suggest Hidden Replies Again** brings back the ones you hid). **Commands:** a command you ran shows in the chat as yours, wherever you ran it (`/context`, `/model fable`, a skill, `!ls` after a `$`), in the code font, with what it printed under it in Claude's colours. The box's `/` list offers Claude's commands (as of Claude Code 2.1.318), yours and the project's, each where it runs: most run from here (`/compact`, `/context`, `/recap`, `/rename`, `/goal …`, your commands and skills); `/permissions` opens the view's Permissions tab (*Talpy Den*); one that needs Claude's own panel or a dialog (*Terminal*: `/config`, `/btw`, `/clear`, `/add-dir`, and `/model` and `/effort`, which save your default for every new chat) opens in the chat's terminal with the command typed in for you to press Enter there (into one of this window's terminals or its tmux pane, into its Claude Code panel's input; elsewhere it's on the clipboard to paste there), so a background chat never sits in a panel nobody sees. One that can't run on that chat is greyed, and the line under the box says why: a shell command (`!ls`) in a chat that isn't running or a new one (Claude would read it as a message), a command for Claude's own panel in a new chat (start it first). Your message goes the way the chat can take it: typed into its terminal when it runs in one of this window's terminals, or into its tmux pane; put into the input of its Claude Code panel (press Enter there); into a running background chat, as `claude agents` answers one (while it works, it takes it once it can; a terminal that shows it stays on it); or, for a chat that isn't open, the chat goes on with it in the background (`claude --bg --resume`, the same chat). A terminal outside VS Code takes no text from outside, so there you choose: send it, and Claude there quits and the chat goes on in the background, or copy it and open its terminal. An SSH host's chats work the same way. A notification takes a reply too (**Reply…**).

**Dictating a reply:** the microphone under the reply box records what you say (up to five minutes) and writes it into the box, with speech to text that runs on this computer: what you say never leaves it, and the recording is deleted once it's written down. The first click offers to set it up, with no sudo: faster-whisper from pypi.org in a Python environment of its own and its base speech model from huggingface.co (about 600 MB), in `~/.local/share/talpy-den/whisper` (with whisper.cpp installed, that's used and only a model is downloaded). **Talpy Den: Dictation Models…** downloads, deletes or picks a model (up to 1.5 GB each), or removes faster-whisper; `talpyDen.dictateLanguage` sets the language. One setup serves Talpy Chat in VS Code and in Plasma.

**Permission prompts:** a chat waiting for a permission shows the command, or the file and its change (any other tool, an MCP server's or a page fetch: what it's called with, as `key: value` lines, the first three in a row and a notification, all of them in its tab), with **Allow once**, **Always allow** and **Deny** (with a note for Claude), in Claude's own order, in its row, its tab and its notification (a prompt that takes the place of the one shown, a parallel subagent's say, says *New prompt* and its buttons wait a moment, so a click meant for the one before doesn't answer it). A notification shows a command of more than 3 lines or 200 characters (or arguments that long) only in part, with *… N more lines: Open to read it all*, and offers **Open** (the chat's tab, with all of it), **Allow once** and **Deny** for it; **Always allow** is then in the row and the tab. In a background chat's tab, your reply answers what it asks, as typing in its own prompt does, and the chat is never stopped for it: **Deny with this note** (a plan: **Keep planning with this note**), or one question's answer in your own words (several: **Decline with this note**). That needs **Talpy Den: Answer Permission Prompts from Talpy Den…**: it adds a hook to each Claude profile's `settings.json` (and on the SSH hosts shown) that hands each request to Talpy Den. Claude still asks in the chat too; whichever you answer first counts. **Always allow** does what Claude suggests, as its own *don't ask again* does, and its tip (in a notification, a line next to the button: *Always allow: …*) says what that is and where it goes: a rule (`Bash(git push:*) in this project (.claude/settings.local.json)`), access to a folder, or all edits in this chat (accept edits mode). Chats in tmux can be answered without the hook, with their dialog's keys, unless the prompt may be about another call than the one shown (a subagent's, or one of several calls Claude made at once): those you answer in the chat.

**Claude's questions:** when Claude asks you a multiple-choice question, its row and its tab show each question with its options (choose one, or any for a question that takes several) and a field to answer in your own words, then **Send answers** or **Decline…** (with a note for Claude). Its notification has a button for each option when it's one question with one answer, then **Other…** (your own words); with more questions, **Answer…** goes through them one by one in VS Code's pickers. Your answers reach Claude as they would from its own dialog. This takes the same hook (without it, the question shows, to answer in the chat).

**Review:** the tab's **Review** lists the files a chat changed with their added and removed lines, against how they were before the chat (from Claude's own backups), each with its diff (side by side where the tab is wide enough, else one under the other: the switch in its corner, `talpyDen.diffSideBySide`), **Diff** (VS Code's diff editor) and **Undo**; **Undo all** puts them all back (a file the chat made is deleted for good, and the question says so). **Commit these files…** commits only this chat's files (yours stay as they are, and files git ignores are left out) with a message made from its name and Claude's recap, that you edit first. Finished chats that changed files say **to review** until you **Mark reviewed** (or until they change files again), with whether tests ran and passed after their last edit.

The window button beside a chat and a click on its pet open the chat itself, on the machine it's on (with `talpyDen.clickOpensPane` off, so does a click on its name): in VS Code's terminal here, on the window's host, or through `ssh -t` for another host. A chat already running in one of this window's terminals is brought to the front; a chat of the Claude Code extension is revealed in it.

**New chat** (the speech bubble with a plus next to an account, or **Talpy Den: New Chat…**) asks where: first **In a Talpy Chat tab** (an empty tab for that account and folder, with a ⚙ line for the model, effort and permission mode; your first message starts the chat in the background, shown at once with *Starting…*; a task goes as its first message; a folder Claude doesn't trust yet starts in a terminal), then in a terminal, in one of the account's recent folders or any other, or as a Claude Code chat tab in this window. **Start with a task…** first asks what Claude should do: the chat starts with it (in a terminal at once, in a Claude Code tab typed in for you to send), and can also run **in the background** (`claude --bg`: no window, listed right away; only in folders Claude trusts already, since it can't ask there). **Later, at a time you pick…** queues it for a day and time instead, and when the account is at its usage limit, **After the limit resets** queues it for a minute after the limit resets (the queue is shared with Talpy Den on Plasma, which starts it too if VS Code isn't running). Its ⚙ line (the model, reasoning effort and permission mode, *change…*) picks what a chat in a terminal or the background starts with; the next one starts with the same (`talpyDen.newChatModel`, `newChatEffort`, `newChatMode`). The Claude Code tab is offered for accounts on the window's own machine (this computer, or the Remote-SSH host); it starts in the window's folder, on the account the Claude Code extension is set to, and the menu says so when that's another account. Without the `claude` command on that machine, the menu says so and offers only the Claude Code tab.

**Recent chats** reopen in Talpy Chat, in a terminal (`claude --resume`) or in a Claude Code tab: the **Talpy Chat | Terminal | Claude Code panel** switch above them picks which (kept in `talpyDen.reopenIn`; Terminal unless you pick another), and so does every other way to reopen a chat that isn't running (**Open its window** in its tab, its row, **Find a Chat**). In Talpy Chat, your next message goes on with it in the background, and what it asks is answered in its tab (chats Talpy Chat starts or wakes get Talpy Den's permission hook for themselves alone, unless it's on for every chat); with Talpy Chat picked, a background chat no terminal shows opens there too, and **Open in a terminal** in its tab shows it in one (`claude attach`). **Answer it in a terminal** is there for a prompt Talpy Chat can't answer. This computer's chats only for now: an SSH host's or a container's open in a terminal. A Claude Code panel opens in the window that has the chat's folder: this one, another, or a new one (an SSH host's chat: connected to it). A half is greyed out where it can't work, and its tooltip says why: no `claude` command on the chat's machine (the chats then reopen in Claude Code), or Claude Code not installed or on another account.

A running chat opens where it runs: its terminal, or its Claude Code panel. One in a terminal can **move to a Claude Code panel** (the → button of its tab or of its row, when Claude Code is on the chat's account): it asks first, then Claude quits in the terminal, which stays open, and the chat reopens in a Claude Code panel (two Claudes on one chat would both write to it). A chat that's working or waiting for you is stopped only once you say so (**Stop and Move**: the current step is cut off), and an idle one that got back to work since you asked isn't touched.

**Stopping and interrupting** (■, asks first, saying what will happen): a background chat is stopped with `claude stop`. Any other running chat can be stopped whatever it's doing: in a terminal, Claude quits as when its terminal closes (the current step is cut off, the terminal stays open, and the chat moves to Recent chats); in a Claude Code panel it's like the tab's own stop button (the tab says *Interrupted*, keeps the chat and goes on with your next message). A working chat in one of this window's terminals, or in tmux, can be **interrupted** instead: Ctrl+C, as if pressed there, which, like the Claude Code tab's stop button, stops the turn and its subagents (background ones too) and keeps the chat open. Stopping ends every subagent of the chat, since they run inside its Claude, and an idle chat that got back to work since you asked isn't touched. For a chat that keeps going after usage limits, the question says so and offers **Stop** (Keep going stays on, for the next limit) and **Stop and turn Keep going off**.

Each chat shows its model and reasoning effort (*Opus 5.5 · max*, from the status line), and each subagent the model it runs on.

## Requirements

- VS Code 1.90 or newer.
- Python 3.7+ on this computer (`python3`, or set `talpyDen.pythonPath`) and on every SSH host you pick.
- Linux on this computer for its running chats to show (they are found through `/proc`); SSH hosts work from macOS too. VS Code installed as a package (`.deb`, `.rpm`, Arch's): a Flatpak VS Code runs extensions in a sandbox that can't see Claude's chats.
- Claude Code. A plain `~/.claude` is all it needs; more profiles (`~/.claude-*`, `$CLAUDE_CONFIG_DIR`, `talpyDen.extraConfigDirs`) are picked up as well. `claude` is found on PATH, in `~/.local/bin` and npm's, bun's, Volta's, pnpm's and nvm's folders, or on your login shell's PATH.
- For plan usage bars: `jq`, and the status-line snippet (next section).

## Plan usage bars

Claude Code hands plan usage only to its status line. **Talpy Den: Set Up Plan Usage Bars…** adds a small snippet that keeps a copy of it:

- a status line that runs a script reading its input (`input=$(cat)`) gets the snippet after that line, the way the repository's `install.sh` adds it (the two never add it twice);
- a profile without a status line, or with another kind of command, gets a small wrapper as its status line, which keeps the copy and then shows what the status line showed before.

It shows what it will change (and the diff, if you like), asks, and backs up every file it changes. **Remove the Plan Usage Status-Line Snippet** undoes it. The bars fill in after the next reply in each account's chats.

Claude's own VS Code panel runs no status line, and Claude Code updates its own copy of the usage only when `/usage` runs. So while a chat of an account works and its numbers are more than 5 minutes old, Talpy Den asks Claude Code for them (`claude -p /usage`, hooks off, no chat saved; no tokens), at most every 5 minutes per account. `talpyDen.usageRefreshMinutes` sets those minutes (`0`: never).

## Privacy

Nothing leaves your computer except the `ssh` connections to the hosts you pick. There is no telemetry, and the view loads nothing from the internet. Talpy Den calls no Anthropic API itself; when an account's plan usage is more than 5 minutes old while one of its chats works (in Claude's own VS Code panel, which runs no status line), it asks Claude Code for it, at most every 5 minutes per account (`talpyDen.usageRefreshMinutes`; `0` turns it off): `claude -p /usage` on that account, hooks off and no chat saved, which fetches it from Anthropic the way `/usage` does (no tokens). Nothing about your chats is sent.

With **Live Mode** on, a hook (`~/.local/share/talpy-den/live-hook.py`, named in each profile's `settings.json`) writes each chat's last steps to `~/.cache/talpy-den/live/<session>.json`: the tool and its file name or command (cut to 60 characters) and the first line of Claude's last reply. A file goes once its chat has said nothing for 3 days; turning Live Mode off takes the hook out again. The downloads: with `talpyDen.recapCurrency` set to a currency other than US dollars, the **Recap** tab fetches the European Central Bank's public exchange rates (`https://www.ecb.europa.eu/stats/eurofxref/eurofxref-daily.xml`) at most every 6 hours while it's open; setting up dictation downloads faster-whisper from pypi.org (with `pip`) and a speech model from huggingface.co, as does downloading another model. None of them carries anything about you or your chats. The microphone is used only while you dictate: the recording goes to `~/.cache/talpy-den/dictation` (yours alone), is written down on this computer and deleted right after.

What it reads, all of it written by Claude Code itself: its list of running chats (`<config>/sessions`), background jobs (`<config>/jobs`), transcripts (for token totals, chat titles, subagents, what a chat is doing and which files it changed), task lists (`<config>/tasks`), the backups Claude makes before it edits a file (`<config>/file-history`, to compare a chat's changes), `history.jsonl` (recent folders, and your prompts for **Find a Chat…**), the plans chats wrote (`<config>/plans`), Claude's memories (`<config>/projects/<folder>/memory`) and each account's `CLAUDE.md`, the account name and plan from `.claude.json`, and the status-line copies in `~/.cache/talpy-den/statusline`. The **Recap** tab reads the transcripts too, and keeps what it read in `~/.cache/talpy-den/week-3.json`; it calls no model. A rule you **Allow** in the **Permissions** tab is one entry in the `.claude/settings.local.json` of the folder its chats started in (only there, never your user settings), and `~/.cache/talpy-den/rules.json` remembers it so **Undo** can take it back. **Revoke** on one of the permissions you gave takes that one entry out of the settings file it's in (your user settings or a folder's `.claude/settings.local.json`; never a folder's `.claude/settings.json`, which git shares). A chat's tab reads its transcript; what you send there goes to Claude as your message. Answering permission prompts takes the hook you turn on with **Answer Permission Prompts from Talpy Den…** (`~/.local/share/talpy-den/permission-hook.py`, named in each profile's `settings.json`; it writes each request to `~/.cache/talpy-den/permissions` while it waits, and removes it once answered), or the dialog's keys in tmux. **Undo** writes a chat's files back as they were before it (a file it made is removed), **Commit** runs `git add` and `git commit` on only the chat's files, and **Mark reviewed** is kept in `~/.cache/talpy-den/reviewed.json`. A picture you paste into a reply is saved in `~/.cache/talpy-den/images` (yours alone, deleted after 30 days); for an SSH host's chat it's copied to the host's only once you click **Copy**. It writes only to `~/.cache/talpy-den` (caches, which chats, plans, memories and projects you hid, the tasks you queue until they start, copies of the files a comparison shows, kept for a day, pictures you paste), `~/.local/share/talpy-den` (the hooks' scripts and, once you set dictation up, its speech engine and models) and, if you ask for it, the status-line change above, the links of the chats and plans you share (see below) and the accounts you add or remove. **Delete…** (it asks first) moves a chat's transcript with its subagents and checkpoints, a plan's file or a memory's file to the Trash (an SSH host's to that host's), and takes that memory's line out of its folder's `MEMORY.md`. A task you start a chat with goes to Claude, which runs it like a prompt you type (with a plan you carry out, the plan's text is part of it); so does feedback on a plan you send (your comments and what you changed), which goes on your clipboard when the extension can't type it in.

**Logins stay Claude's.** Logging in and out is Claude Code's own command (`claude auth login` in a terminal, where you sign in on Claude's pages in your browser; `claude auth logout`). The extension never opens a login (`.credentials.json`), never sees a password, token or code, and writes nothing of them to its log. A login terminal is a transient one: VS Code neither keeps its screen nor restores it after a reload. **Claude Accounts…** asks `claude auth status` whom each account is logged in as and shows the email address only in that menu. Removing an account deletes its `.credentials.json` (without opening it) after the logout, so no login ends up in the Trash. On an SSH host, the login runs there over ssh, and the code you paste goes straight to Claude on the host.

## Good to know

- Every VS Code window runs its own copy; only the window you used last shows notifications and plays sounds. "Away" means no VS Code window was in use, so switching between windows isn't an absence.
- Talpy Den on Plasma and GNOME uses this extension through its `vscode://wzaielamri.talpy-den/…` links: a chat's changes open in its changes view (without it, one diff per file), a chat in one of VS Code's terminals brings up that terminal, and Plasma's plans and subagent runs open in Talpy Den's tab for Markdown (**Open plans and runs in: VS Code**).
- With Talpy Den on Plasma or GNOME running too, both notify: turn notifications off in one of them.
- On KDE Plasma, a chat running in a terminal outside VS Code (or in another VS Code window) is brought to the front the way Talpy Den on Plasma does it (Konsole tab, window); on GNOME too, while Talpy Den's GNOME Shell extension runs (GNOME 43, 44, 49 and 50; log out and in after installing it). Elsewhere, and on GNOME without it, the view says where the chat runs. On GNOME, sounds use GNOME's sound theme.
- **Talpy Den: Toggle Demo Data** shows made-up chats (for screenshots, or to try it without Claude Code).
- **Sharing a chat** hard-links its transcript into each account's profile, so whichever account continues it writes to the same file; its subagent folder and undo checkpoints move to `~/.local/share/claude-status/shared-chats`. No tokens, hooks or settings are involved. A shared chat can be open in one Claude at a time: the view won't share or unshare one that's open, so close it on one account before you resume it on another. Everything in the chat goes to the account that continues it. **Keep only on …** undoes it. **Continue on …** opens the chat like any other: in VS Code's terminal, or your desktop's with `talpyDen.openIn` = `system`. On an SSH host (Remote-SSH's or a picked one) with two or more accounts it works the same, between that host's accounts; the sharing script goes over ssh like the status script, so nothing is installed there. A chat can't move between this computer and a host.
- **The default account** (**Change the default account…** in the hover of Talpy Den's status bar item, run **Talpy Den: Default Claude Account…**, or **Make Default** in Claude Accounts) is the one VS Code's Claude runs on: it sets `CLAUDE_CONFIG_DIR` in VS Code's `claudeCode.environmentVariables` and reloads the window (other windows offer to reload). Where `~/.claude` is a link, it's pointed at the account too, so plain `claude` in a terminal runs on it as well; a `~/.claude` folder stays as it is. It's refused while that would cut a chat off: one working in VS Code's Claude (the reload), or any Claude running through the name `~/.claude` (in a terminal, VS Code or the background: it would go on on the other account). In a Remote-SSH window it's the host's default: Claude Code there (a machine setting) and the host's `~/.claude`. Remote-SSH windows read the VS Code setting too: on a host without the folder, set `"claudeCode.environmentVariables": []` in its Remote Settings.
- **A second account to share with** is a second Claude config folder logged into a *different* Claude account (profiles on the same account count as one): **Talpy Den: Add Claude Account…** makes one (`~/.claude-NAME`) and opens Claude's login for it; you sign in with the other account. Its settings can be linked to another account's: `settings.json` (your status line too, so its plan usage bars work), `CLAUDE.md`, keybindings and your own skills, agents and commands; the login, MCP servers, plugins and the skills claude.ai syncs stay per account. Its `claude-NAME` command (`~/.local/bin`) runs Claude on it in any terminal. Logging out isn't done while chats run on the account, and only a `~/.claude-NAME` folder that no chat, `~/.claude` or VS Code's Claude uses can be removed. On an SSH host it's the same, over ssh with nothing installed there: the login runs there in a terminal (you paste the code Claude gives you), and a removed account goes to the host's Trash. Sharing needs your Claude folders and `~/.local/share` on one filesystem (hard links can't cross disks or partitions); it checks first and says so otherwise.

## Development

The extension is the `vscode/` folder of the [Talpy Den repository](https://github.com/wzaielamri/talpy-den), next to the Plasma and GNOME code; these run in that folder:

```sh
npm ci
npm run build          # dist/: the extension and the webview
npm run check          # type-check both
npm test               # unit tests, and the backend on made-up homes
npm run watch          # rebuild on change; F5 in VS Code starts a test window
node esbuild.mjs --harness   # dev pages: look at the view with demo data in a browser
```

`vendor/` is what the extension takes from the rest of the repository: its Python backend (`package/contents/code`), Talpy (the pet's drawing, moods and actions, `package/contents/ui/talpy`), `codeview.mjs` and the status-line snippet. Every build copies them there from the rest of the repository (`node esbuild.mjs --vendor` only copies), so change them where they are: `vendor/` isn't committed.

Releases and the check that keeps the repository publishable are described in the repository's [development notes](development.md).
