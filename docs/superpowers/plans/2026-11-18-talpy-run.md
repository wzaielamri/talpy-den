# Talpy's Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second game for the big Talpy, an endless run (press to jump, hold ↓ or the right button to dig, faster and thicker as it goes, one bump ends it with the distance and the best), in the Plasma widget and VS Code.

**Architecture:** The game logic is a `Run` class in the shared `package/contents/ui/talpy/games.mjs` (beside `Peekaboo`, same contract: `start/tick/hit/stop/on/holes`), plus press/release input and plain-data `things`. Its drawings (`drawThing`) live in `talpy.mjs`. The two hosts (`Pet.qml` + `PetStrip.qml` + `main.qml`; `pet.ts` + `stage.ts` + `pets.css` + `view.ts`) start it by name, grow the stage and fade its status while it's on, route presses and keys to it, draw what it says, and keep the best.

**Tech Stack:** Plain ES2017 modules (Qt's JS engine and the webview), QML (Plasma 6), TypeScript (VS Code webview and extension), node-driven Python unittest (`tests/test_games.py`), `node --test` (vscode).

**Spec:** `docs/superpowers/specs/2026-11-18-talpy-run-design.md`

## Global Constraints

- `talpy/*.mjs` stays plain ES2017 (see `paths.mjs`); `games.d.mts` / `talpy.d.mts` type every new export for the webview.
- Nothing ticks, draws or listens for keys unless a run is on; at most a handful of `things`, arrays reused, nothing allocated per frame; hosts tick at `petFrame` (60 fps).
- Clicking Talpy still pets him and the headline/ticker still open chats **when no run is on**; while a run is on every press on the stage is the game's.
- A chat that needs you, Esc, a click outside the stage, the stage out of sight end the game at once (as Peekaboo).
- Not offered (menu or four-click pick) when `root.onDesktop` or `root.lessMotion` (Plasma) / `reducedMotion()` (VS Code).
- Plasma's menu has no submenus (project rule): one `PlasmaCore.Action` per game.
- Its own look: no dinosaur, cactus, pterodactyl, grey pixel style.
- Words in Plasma through `i18n`; the end line fits one line at 380 px.
- GNOME is not changed. Python 3.7 still runs the suite.

## Review Focus

- A chat starts needing you mid-run: the run ends, the stage shrinks back, the status fades back in, the distance still counts for the best (Task 3 and Task 4 host tests read this path).
- Right-click on the stage: digs while a run is on, and does what it did before when no run is on (Task 3, Task 4).
- Keys: Space/↑/↓ do nothing when no run is on, and in VS Code never when the key went to a text field (the chat reply box) (Task 4).
- The popup closes or the view hides mid-run (stage out of sight): over, and it opens again on the normal 6-grid-unit stage (Task 3, Task 4).
- A very narrow (380 px) or very wide stage: obstacles enter from beyond the right edge, a gap is clearable at every width, the end line fits one line (Task 1 tests run two widths; Tasks 3/4 render at 380 px).

### Task 1: The `Run` game (logic)

**Files:**
- Modify: `package/contents/ui/talpy/games.mjs` (add `Run`, `GAMES`, `pickGame`)
- Modify: `package/contents/ui/talpy/games.d.mts`
- Test: `tests/test_games.py` (a new `RUN` node script and `RunTests`)

**Interfaces:**
- Produces:
  - `export const GAMES = ['peekaboo', 'run']`
  - `export function pickGame(talpy, host, name)`: `name` `'peekaboo'` or `'run'` gives that game; `''`/undefined picks at random among `GAMES`, without `'run'` when `host.runOk && !host.runOk()`.
  - `class Run` with `name = 'run'`, `on`, `state` (`'ready'` first 2 s, `'run'`, `'over'`), `holes` (`[{x, open}]`: his dig hole, open 0..1, else `[]`), `things` (`[{kind, x, y, w, h, frame}]` stage px, `kind` one of `'pebble' 'stone' 'pot' 'pebbles' 'crow' 'crowHigh' 'tuft'`; `'tuft'` is ground decor, never hits; `frame` 0 or 1, a crow's wings, flipped about every 150 ms), `lift` (px he's above the floor), `digging` (bool), `meters` (int), `best` (int, from the host at start), `newBest` (bool), `hint` (`''`, `'start'`, `'dig'`), `start(now, wake)`, `tick(now)`, `hit()` (true: a click on him is the game's), `stop()`, `press(what)` (`'jump'` or `'dig'`), `release(what)` (`'dig'`).
  - `RunHost extends GameHost` (d.mts): `stage()` also returns `height` (the grown stage, px); `best(): number`; `saveBest(meters: number): void`; `grow(on: boolean): void`; `runOk?(): boolean`; `say(what)` with `'bump'` and `'best'` added to `GameWords`.

Then `RunTests`:

  - `test_it_grows_the_stage_and_waits_2_s_before_the_first_obstacle`: `grow(true)` at start; `hint == 'start'` and no hitting `thing` before 2000 ms.
  - `test_with_no_input_the_first_obstacle_ends_it`: (a) ends with `state == 'over'`, `meters > 0`, `say('bump')`, the game still `on` (end screen), `saveBest` not called with less than `best()`.
  - `test_a_player_who_jumps_and_digs_runs_far_and_faster`: (b) passes 400 m; speed (meters per second over the last 10 s) is above 1.5× the first 10 s and never above the cap; `crow` appears only after 200 m; the first crow comes with `hint == 'dig'`.
  - `test_every_gap_is_clearable`: in (b) and (d), for every pair of consecutive hitting things, the gap ≥ the jump's length at that speed + landing room.
  - `test_dig_passes_under_crows_not_ground_things`: a crow over him while `digging` doesn't end it; a pebble while `digging` does.
  - `test_a_new_best`: an auto-player run past 120 m ends with `newBest` and `saveBest(meters)` once; `say('best')`.
  - `test_the_end_screen_runs_again_or_ends`: in `'over'`, `press('jump')` starts a new run (`state` back to `'ready'`, `meters == 0`); with no press, 10 s later `on` is false, `grow(false)` called.
