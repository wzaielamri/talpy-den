# Deep Dig (and the Run's cookies and physics) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **The owner's choice for this plan: built natively, without agents (superpowers:executing-plans).**

**Goal:** A second high-score game, Deep Dig (Talpy digs down, you steer him round what's buried), in Plasma and VS Code, sharing the Run's machinery; and the Run gets cookies and correct physics.

**Architecture:** A shared base class for scored games (`scored.mjs`: slots, the whole-frame step, the end and its waits, the best, the score with its cookie bonus) that `Run` (`games.mjs`) and the new `Dig` (`dig.mjs`) extend; the hosts (Plasma `Pet.qml`/`PetStrip.qml`/`main.qml`, VS Code `pet.ts`/`stage.ts`/`view.ts`) host "a scored game", not "the Run". Things stay pictures drawn once and moved (`drawThing` in `talpy.mjs`).

**Tech Stack:** plain ES2017 modules (Qt's JS engine and the webview), QML (Plasma 6), TypeScript (VS Code webview/extension), Python unittest driving node (`tests/test_games.py`).

**Spec:** `docs/superpowers/specs/2026-11-19-deep-dig-design.md`

## Global Constraints

- Plain ES2017 in `package/contents/ui/talpy/` (no `?.`, `??`, class fields); `.d.mts` types beside each module.
- English words through `i18n` in Plasma.
- Light: 60 fps while a game is on, nothing ticks/draws/listens while off; no stage-sized canvas painted every frame (each thing a picture drawn once and moved).
- Fits a 380 px popup: sizes and the gap rule by his body's size and the stage's width.
- Saved bests keep their keys: Plasma `runBest`, VS Code `talpyDen.runBest`; new: `digBest`, `talpyDen.digBest`. `"suggestReplies"` stays last in `main.qml` `sharedKeys` (test_pets).
- Not offered on a desktop-placed widget nor with less motion (`runOk`), for the Run and Deep Dig.
- The end: 5 s wait (`RUN_END_MS`), presses taken from 450 ms (`RUN_AGAIN_MS`); Esc, a click outside, a chat that needs you, the stage out of sight end it at once and it still counts.
- GNOME untouched. No co-author or AI attribution lines in commits. No push.
- The owner's bar: "make sure the physics are correct, not weird movements, and also nice design".

## Review Focus

1. **A long frame (a hidden tab, a GC pause, dt clamped to 0.1 s) at top speed:** a thin thing (a pipe, a log) in his way still hits him; nothing is stepped over. Test in Task 4 (`test_a_long_frame_still_hits_a_thin_thing`) and Task 2 for the Run's fall.
2. **A narrow popup (380 px) and a wide view (900 px):** every Deep Dig row leaves a reachable gap; the seeded player never bumps to 1000 m at either width. Task 4 (`test_a_steering_player_digs_far_at_any_width`).
3. **The view resized mid-dig:** his x and his aim are clamped into the new width at once, rows that come after use it. Task 4 (`test_resized_mid_dig_he_stays_inside`).
4. **No mouse at all (keys only, or the mouse never over the stage):** he stays where he is until steered; ←/→ steer him with the same physics. Task 4 (`test_keys_steer_with_the_same_physics`).
5. **The theme switched mid-game:** every visible thing's picture is drawn again for the new theme (Plasma `relook` on `darkTheme`; VS Code's picture key has the theme). Task 1 asserts both hosts' wiring (`test_pictures_follow_the_theme`).
